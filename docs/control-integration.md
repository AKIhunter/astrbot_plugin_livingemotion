# 掌控感：情绪计算与聊天表达

适用 LivingEmotion 0.10.2。

掌控感 `control` 表示 TA 此刻能否应对互动、解释处境、表达意愿，不是开心、好感或知识准确率。知道如何解释时，即使生气也能有高掌控；熟络不必高，冷淡不必低。它沿用现有状态范围：同一实例和人格共享模式下共享数值，关闭共享后按会话分开；聊天正文、关系和三项对象情绪的来源继续隔离。

## 开启与更新

在「设置 → 情绪」开启模型辅助情绪分析，并选择有效模型。关闭后不新增掌控感样本，旧值按 60 分钟半衰期回落到中性 0.5。本地规则不修改掌控感。

复用现有联合分析，默认最小间隔 600 秒，不新增调用、额度或等待。有效读数先让旧值衰减，再以 EMA 0.2 写入；置信度须至少 0.75。缺值或低置信样本不写，非法输出沿用原有校验失败处理。冷却期间委屈、受伤、害羞的专用分析不更新掌控感。写回仍由原事务、generation、owner 和版本校验保护，冲突不重试模型。

`control_at` 是掌控感读数的时间基准；更新它不改变四维的 `updated_at` 或衰减基准。

## 情绪投影

设 `D = 2 × control − 1`，原四维公式得出 `E₀`：

| 情绪 | 最终公式 |
| --- | --- |
| 愤怒 | `clamp(愤怒₀ × (1 + 0.30D))` |
| 悲伤 | `clamp(悲伤₀ × (1 − 0.20D))` |
| 恐惧 | `clamp(恐惧₀ × (1 − 0.40D))` |
| 开心、惊讶、关爱 | 原公式不变 |

`clamp` 限制在 0～1，中性 0.5 与旧结果一致，零情绪不会凭空产生。这是软件启发式参数。开心保持原公式及 5 分钟上升 5 点、下降 10 点的刺激预算。

页面、当前情绪 API、聊天、历史重建和新梦境共用 `six_emotions`。更新后可能改变新梦境基调及噩梦候选；已有梦境不重新计算。LivingHello 使用新的负面情绪数值：有效图片许可存在时只影响措辞，许可缺失时仍可能触发其原有负面情绪随机拒绝分支。

## 聊天表达

`control_expression` 从已衰减的当前快照生成 `control` 与 `control_style`，普通回复、主动聊天和控制台模拟共用。

| 范围 | 表达 |
| --- | --- |
| 小于 0.35 | 谨慎解释，必要时澄清一个关键点 |
| 0.35～0.65（含边界） | 按当前情绪和人格自然表达 |
| 大于 0.65 | 更直接、坚定地表达意愿和边界 |

说明随动态状态注入，不依赖可关闭的通用提示词。掌控感不替代事实证据，不增加权限，不逃避已接受任务，不索取安慰、不攻击或压迫对方。控制台手选情绪仍优先决定情绪种类，掌控感只调节表达方式。主动发送评分、候选权重、次数和冷却保持原规则；委屈、受伤、害羞继续由原有对象链路判断。

## 历史与迁移

数据库 v9 为 `emotion_samples` 增加可空 `control/control_at`，新样本保存原读数及其时间基准，按每个历史时刻衰减。升级不回填旧历史、不重写现有状态或关系。

历史返回 `control_basis`：`recorded_decay` 表示采样后衰减，`legacy_control_unknown` 表示旧样本缺少底气，`uncollected` 表示没有样本。旧样本按中性计算，页面说明该缺口；基线是否缺失仍由原 `basis` 标记。迁移幂等，当前值不得用于补算旧历史。

## 实现位置与验收

领域层负责纯计算；运行时负责模型输入和注入；存储层负责迁移与采样，不从领域层访问模型或数据库。

验收覆盖中性兼容、零输入、有界和单调性、开心预算、表达边界、模型置信度、事务冲突、历史重建/重启、共享与隔离、普通回复关闭通用说明、主动聊天及模拟。测试使用虚拟时间与打桩 Provider，禁止联网。实际模型语义表现须另外授权并实测；不将离线链路通过表述为真实模型理解通过。

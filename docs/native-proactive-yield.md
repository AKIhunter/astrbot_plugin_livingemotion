# 宿主定时问候与随机主动让行

适用 LivingEmotion 0.10.1；让行规则始于0.6.2，无新增配置项。

`proactive_native_yield=true` 时，仅同一会话在宿主定时问候前后各 15 分钟跳过随机主动检查。正常每天 08:00 的早安对应 07:45–08:15，其余时段继续原随机流程。

## 判断链路

`runtime/proactive_arbiter.py` 只读宿主 `data_v4.db / cron_jobs`：

1. 保留原有启用状态与主动问候识别规则。
2. 从 `payload.session` 读取完整目标会话；不会凭 sender_id 或相同号码扩大到其他平台、群聊。
3. 从 `next_run_time` 和 `last_run_at` 读取宿主已排定时间及最近执行时间。宿主数据库无时区日期按 UTC 解释；带时区日期按其偏移换算为 Unix 秒。
4. 将最少元数据缓存五分钟，不导出 payload 或私密 note。
5. `yielding_jobs()` 每次用当前时刻判断目标与 ±900 秒窗口。缓存不会把“存在任务”变成全天让行；最新执行时间保留刷新后的后窗口，晚到的实际执行也避重。

`runtime/proactivity.py / maybe_proact()` 使用 `rebuild_route(context)` 匹配当前真实来源会话。命中才返回；未命中沿用原事务机会、概率、空闲、冷却、作息、额度、素材及发送前校验。

缺失目标、缺失时间、坏 payload、旧表结构、未检测到宿主目录均不产生全局让行。所有命中的任务参与判断，不再只取前五条。

## 配置与运行边界

开启后在宿主定时任务面板设置目标和时间；关闭后不再避让宿主任务。开关仍是平铺 bool，默认 true，无新增配置项或存量迁移。

只影响随机主动；承诺兑现、晚安、补读等沿用原链路。任务设置变更最长五分钟读回，宿主任务不由插件修改或删除。这里依据宿主已经保存的时间，不自行解析 cron 或新增调度依赖。

窗口结束后，过期随机机会按原规则跳过并重新排期，不补发旧机会。因此“恢复随机检查”不等于 08:15 立即发送。重启后仍需真实入站私聊恢复实时来源。

## 离线验证

新增 `tests/integration/test_native_proactive_yield.py` 的 33 项测试，覆盖：

- ±900 秒及窗口外一秒；中午不让行。
- 不同平台、会话、私聊 / 群聊；坏或缺失目标。
- UTC、显式时区、跨日、缺失时间及旧表结构。
- 刷新后下一次时间推进，最近执行仍保留后窗口。
- 第六条任务能参与判断。
- 真实 Application 与 SQLite：窗口内零生成 / 零发送，窗口外恢复普通机会；过期不补发、下一机会可执行。
- 承诺关闭时正常刷新宿主缓存；关闭让行开关保留普通机会。

本地及服务器模型、平台发送均打桩并禁止网络连接，不调用真实付费模型。原主动回归和全量回归同时通过。

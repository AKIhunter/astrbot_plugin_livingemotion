# 睡眠、精力与回复票据

适用0.6.0。设置入口：“设置 → 长夜”；默认使用night_policy_version=2，
v1算法仍兼容。全部字段说明见[配置参考](config-reference.md)。

## 唯一睡眠许可

`allow_sleep`是总开关。关闭后立即清醒、精力100%，停止作息睡眠、午休、
疲劳和回复耗能；重开从当前时间恢复计算，不补扣关闭期间。
旧`night_schedule_enabled`不再出现在公开schema或页面，也不能授予睡眠；
`nap_enabled`、时间参数、补觉参数都必须先满足总许可。
历史idle、共享人格状态及遗留票据在兼容加载和开关切换时归一，读取页面只投影。
关闭时页面显示当前清醒状态，不用刷新推进持久周期。

## 默认状态规则

| 条件 | 状态 |
| --- | --- |
| 非睡眠且精力>20% | 清醒 |
| 0%＜精力≤20% | 恍惚，可交流 |
| 精力=0% | 困，可交流 |
| 困/恍惚连续安静30分钟 | 补觉沉睡；可靠新鲜人类消息和回复提交重置计时 |
| 补觉恢复到20% | 仍沉睡；到20.1%才转小憩 |
| 小憩满100%或到截止 | 退出，已结束的小憩不因下一次扣能立即恢复 |
| 最晚入睡到实际起床 | 固定沉睡，满精力不提前醒，到期恢复100% |
| 补觉跨入固定时段 | 固定沉睡优先，沿用本周期赖床结果 |

共享人格时，各可靠会话重置同一人格的安静计时，不共享正文。
白天默认不恢复；开启`energy_daytime_recovery_enabled`后，
非疲劳时段按每分钟恢复值恢复，睡眠恢复仍独立。
补觉默认截止于未来基础起床加赖床，赖床只在新周期抽一次并保存。
关闭`recovery_follow_wake_at`后使用`recovery_max_minutes`，默认120分钟；
到期不强制回满，并重新开始安静计时。午休以自己的结束时间截止，满精力不午休。

默认回复耗能2点、疲劳0.5点/分钟、恢复1点/分钟；
旧配置显式值继续生效。状态以0.1点整数和时间余数保存，
跨阈值、固定入睡、起床等边界拆分结算，重复刷新及回拨不重复扣算。
跨日起床可结算固定100%恢复；管理员提前唤醒取消本次固定睡眠恢复奖励。

## 唤醒与在途回复

普通聊天只尝试唤醒小憩，不能唤醒固定或补觉沉睡；成功进入恍惚，不加精力。
默认唤醒10轮、10分钟，从第一条实际提交起不续期。
开始生成占轮数，失败不退轮但不扣精力；首次有效提交才扣一次，
分段、TTS、重复回调不重复扣。

并行准入可乱序完成；额度耗尽后等已准入票据收尾，再按精力结束唤醒窗。
超时、换周期、换身份/代际、进入沉睡或伪造票据拒绝提交。
正常到点睡醒仍允许同周期有效在途回复完成；重启作废在途票据，不重发旧答。
准入、事件和状态写入共享数据库事务。宿主受理不等于平台已送达。

storage/night.py负责事务和票据；projector处理新鲜人类刺激。
离线测试为tests/night/test_sleep_master.py、test_sleep_energy_rules.py、
test_wake_submission.py及集成回复测试；使用真实临时SQLite与虚拟时间。

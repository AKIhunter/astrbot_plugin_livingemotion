# 睡眠与精力规则（当前0.4.3）

精力规则源于0.4.0，0.4.3统一睡眠许可；下文v2计算适用于规则2与有效时区，
旧v1算法保留。但关闭allow_sleep锁满100%/清醒对所有版本与无时区路径都成立。
升级不会覆盖已有显式配置，新默认值只对缺省配置生效。2026-11-19核对当前源码。

## 睡眠总开关

“设置 → 长夜 → 自动作息”只保留 `allow_sleep`（允许 TA 睡眠）。
关闭后立即清醒、精力固定100%，时间与回复都不扣精力，不自动入睡、
午休、补觉或发睡前晚安；手动入睡也须先开启。开启后恢复原精力与作息规则，
午休仍由 `nap_enabled` 单独控制。自动计划需有效时区；关闭无需时区。

旧 `night_schedule_enabled` 仅保留用于读取旧配置，不再展示或接受页面保存。
显式 `allow_sleep` 优先；只有缺少它的旧配置才从旧作息许可迁移。
修改时间、午休或赖床参数不会隐式开启睡眠。关闭会清理本实例全部存量夜间
记录（包括没有活动的会话）；再次开启先更新计时起点，不补扣关闭期间的精力。
页面自动刷新只投影状态，不写记录、不抽取赖床结果。

## 状态与恢复

下表是默认“白天自动恢复精力”关闭时的行为。三个平铺配置位于
“设置 → 长夜 → 精力与清醒”，原生 AstrBot 配置页同样可编辑：

| 配置 | 默认 | 开启或调整后的行为 |
| --- | --- | --- |
| `energy_daytime_recovery_enabled` | false | 开启后，非疲劳时段未睡眠也按“每分钟恢复”回血；睡眠恢复不受开关影响 |
| `recovery_follow_wake_at` | true | 开启沿用下一次基础起床＋赖床；关闭使用补觉最长时长 |
| `recovery_max_minutes` | 120 | 关闭上方截止开关后生效；整数1–1440分钟，从实际补觉开始计算 |

旧配置缺少新键时使用以上默认值，保持原规则。开启白天恢复不会修改夜间消耗、
午休时间或睡眠总开关。补觉配置修改只影响新周期，当前已持久化
截止保持不变，重启不重算。固定夜间沉睡继续优先于自定义补觉截止。

| 条件 | 状态与后续行为 |
| --- | --- |
| 未睡眠且精力>20% | 清醒；不自动恢复 |
| 未睡眠且0%＜精力≤20% | 恍惚；可交流，不自动恢复 |
| 未睡眠且精力=0% | 困；可交流，不自动恢复 |
| 困或恍惚连续安静30分钟 | 补觉沉睡；新鲜可靠人类消息、回复提交会重置计时 |
| 补觉沉睡恢复到20% | 仍沉睡；严格超过20%，即固定精度下20.1%，才转小憩 |
| 小憩到100%或截止 | 退出；之后聊天扣精力不会自动重新进入已完成的小憩 |
| 最晚入睡至本周期实际起床 | 固定沉睡；满精力不提前退出，到期直接恢复100% |
| 补觉跨入固定沉睡时段 | 固定沉睡优先，沿用同一次赖床结果 |

“安静”使用状态所有者的持久计时。开启人格共享时，不同会话的可靠人类消息
也会重置同一人格的计时；不会共享消息正文。夜间疲劳跨到20%时才进入恍惚并
重新计时，避免沿用清醒期间的长时间安静而立即补觉。

默认补觉和补觉转小憩的截止，共用下一次基础起床加赖床。已有未来实际起床时刻时
复用，包括基础起床已过但赖床尚未结束的情况；否则取未来的基础起床日期，
只在新周期入口抽一次赖床并持久保存。不是固定“从现在起8小时”。
计划午休仍以配置的午休结束时间截止，满精力时不进入午休。
关闭“补觉按起床时间截止”后，默认最长120分钟。恢复100%提前结束；到期
不强制回满，按当前精力退出并重新计算30分钟静默，避免低精力当场无限续开。

## 精力计算与配置兼容

| 配置 | 新默认值 | 适用时段 |
| --- | --- | --- |
| `energy_reply_cost` | 2点/次 | 首次有效回复提交；失败、重复回调、分段和TTS不重复扣 |
| `energy_fatigue_per_minute` | 0.5点/分钟 | 夜间疲劳窗口内的非睡眠状态 |
| `energy_recovery_per_minute` | 1点/分钟 | 小憩、沉睡；开启白天自动恢复后也用于非疲劳时段未睡眠的恢复 |
| `wake_reply_limit` | 10次 | 一次聊天唤醒窗口内真正开始的回复尝试 |

以上是代码与schema的新默认值。已有显式配置继续生效，包括已有疲劳值2；
升级代码不会自动把生产存量配置改成0.5。配置定义、保存校验、运行时换算、
前端0.1步进与帮助文案保持同一口径。

精力以0.1点的整数单位保存，时间余数保留到微秒计数。按精力阈值、安静截止、
疲劳时段边界、沉睡开始及起床时刻拆分结算；重复推进和时钟回拨不重复计算。
白天的清醒、恍惚、困默认不恢复，开启白天恢复后使用同一恢复速率；
关闭允许睡眠时始终精力100%。开启时向有效精力区间移动，即使尚处0或100边界，
也保留不足0.1点的时间余数，避免频繁刷新使回血或疲劳丢失。
长时间离线跨过固定起床时刻，仍结算最近固定沉睡的100%恢复，不补发消息。
管理员提前唤醒取消本次固定沉睡，不在原起床时刻重新奖励满精力。

## 唤醒窗口与在途回复

普通聊天只尝试叫醒小憩，不能叫醒补觉沉睡或固定沉睡。成功后一律进入恍惚，
不增加精力。默认10轮、10分钟；窗口从第一条实际提交开始，后续不续期。

真正开始生成占一轮，失败不退轮，也不扣回复精力。额度用满后拒绝新请求，
等该窗口所有已获准回复都提交或失败，再按当时精力判断：60%清醒、20%与15%
恍惚、0%困。窗口超时同样按精力结束；剩余在途回复拒绝提交。
并行回复允许乱序完成，先完成的末轮不能使其他已准入票据失效。
重启取消全部在途票据后，已用满的唤醒窗在下一次状态结算时结束，不重发旧回复。

回复准入、精力事件与状态保存使用同一数据库事务。重复提交不二次扣费。
正常起床清理唤醒会话后，同周期已准入回复可以完成；提前清理、换周期、
换会话、过期窗口、进入沉睡、旧身份/代际或伪造票据仍拒绝。
宿主提交代表回复进入输出流程，不代表平台已送达；无法确定送达时不自动重发。

## 正确性与离线验证

必须始终成立：精力保持0..100；白天恢复关闭时非睡眠不恢复；恰好20%不清醒；固定沉睡不
因100%提前醒；周期赖床不重抽；重复回复不重扣；旧票据不能绕过来源与截止校验。
必须最终发生：安静30分钟进入补觉；补觉超过20%转小憩；满精力或到期退出；
固定到期恢复100%；最后一次生成失败也能结束已耗尽的唤醒窗。

验证使用虚拟时间、真实临时SQLite、全网络连接熔断；没有模型或平台调用。
`tests/night/test_sleep_energy_rules.py` 覆盖20%/20.1%、0%、满精力退出、
安静30分钟、共享消息、重启、只读刷新、跨午夜、1/3/30天离线、
零恢复速率、关闭睡眠、管理员唤醒及并行成功/失败。
固定随机种子20261116比较直接结算与120段随机时间推进的一致性。
`tests/night/test_life_state.py、test_wake_submission.py` 保留事务回滚、
乱序、重复、重启、身份/代际、窗口超时与在途跨正常起床反例。
`tests/integration/test_retro_reply.py、test_submission_reason.py` 验证真实宿主钩子，
使用合成回复，无发送。

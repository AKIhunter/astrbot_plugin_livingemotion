# TA 的生活控制台

本页是改版后的使用与计算说明。配置以 `config.py`、`_conf_schema.json` 为单一来源；
旧版本迁移和旧作息规则的阶段报告仍保留，不覆盖本页的新规则。

## 快速开始

1. 从 AstrBot 插件页面打开 livingEmotion，进入“设置 → 快速开始”。
2. 选择原生人格和 IANA 时区，例如 `Asia/Shanghai`。规则情绪无需配置模型。
3. 核对午休、疲劳、沉睡和起床时间，再启用计划作息与“允许 TA 睡眠”。
4. 想保留日记时选择日记模型，填写住所城市并启用日记。梦境模型可单独选择。
5. 需要长期记忆时选择接入方式、开启读取；本地自动收录另需开启写入并选择向量模型。
6. 保存一次，在顶部选择人格、全局/私聊/群聊与具体来源，查看 TA、关系或长夜。

旧配置缺少 `night_policy_version` 时沿用规则 1，缺少 `persona_shared_state` 时
沿用会话独立状态。要使用新版五档作息，在设置中切到规则 2 并配置有效时区。
新安装原生配置默认规则 2、同人格共享；计划作息默认关闭，不凭空推断时区。

## 页面与范围

| 页面 | 使用方式 |
| --- | --- |
| TA | 大字号当前情绪、四维雷达、精力与五档作息；高于基准的维度单独突出 |
| 人格 | 当前 AstrBot 原生人格及来源 |
| 情绪 | 详细解释 Bot 感受、对方观察与情绪变化，不读取日记 |
| 关系 | 以当前人格为中心的二维力图；平台账号搜索、分页与手动好感修改 |
| 主动行为 | 查看原因与无费用模拟；主动发送按独立开关、范围和额度控制 |
| 长夜 | 当前睡眠、首次回复起算的窗口倒计时、最近24小时精力曲线和事件表 |
| 日记与梦境 | 分开查看日记、梦境；正文遵守原来源权限 |
| 记忆接入 | 当前后端与能力；设置入口通向集中设置 |
| 设置 | 快速开始及人格、情绪、关系、行为、长夜、日梦、记忆分组；高级项折叠 |

全局只是当前人格的管理筛选，不是发送路由。“同一人格共享状态”开启时，
同实例同人格共享 Bot 情绪、精力与作息；关闭时按真实会话分别保存。
私聊/群聊筛选不改变状态所有者。人类观察、关系、正文、记忆和发送来源仍保留真实会话。
切模式保留两套历史，首次采用保守的精力/睡眠限制，不能切换恢复满精力。

白昼与黑夜只改变视觉主题。支持时以点击处为中心圆形扩散；
减少动效偏好下直接切换。宿主 iframe 禁止存储时主题仅本次有效，刷新随系统。

## 情绪与关系

雷达四维基准为愉悦50%、唤醒30%、压力0%、社交需求30%。
页面展示当前值与基准，情绪页再解释变化原因；对方的难过不会直接覆盖 Bot 的心情。

关系以实例、人格、平台和个人账号为键：QQ 使用 QQ 号，B站使用 UID。
展示分值0–100、步进0.1，对应内部0–1000；同号跨平台不合并。
图默认最多200人，表格每页10条；搜索可定位图中未展示的账号。
人格固定在正中，周围留白；人物圆点更小，向四周自然扩散。
实线连接人格与账号，线宽表示好感。虚线表示从记录或授权记忆中推测的
人物关系，如朋友、同事或室友。选择人物后可展开查看陈述、日期与来源。
同群、共同出现、疑问或假设不会建立关系；新的明确否定会撤销旧线索。
推测只用于展示，不改变好感。记忆开关关闭时仅使用记录。
修改携带版本与原因，过期版本返回409，刷新后人工复核。冻结可暂停自动好感变化。
缺少信任、熟悉或边界证据时显示未采集，不从好感分推算这些维度。

## 长夜计算

| 状态 | 聊天行为 |
| --- | --- |
| 清醒 | 正常回复 |
| 小憩 | 归档；按唤醒方式可叫醒 |
| 恍惚 | 可以沟通，保持疲劳表达 |
| 困 | 归档；满足唤醒规则后可叫醒 |
| 沉睡 | 消息只读不回；仅计划起床或已认证管理员手动唤醒 |

午休区间为小憩。夜间从疲劳开始进入恍惚，疲劳开始到沉睡时刻的中点进入困，
沉睡时间点进入沉睡，直到实际起床时刻。赖床从配置分钟区间只抽一次并持久化；
刷新、重启和重复消息不会重新抽取。
关闭“允许 TA 睡眠”后仍记录精力与疲劳表达，但不因睡眠阻断聊天。

精力上限100只读，设置最小步进0.1。默认回复消耗4、疲劳每分钟消耗0.8、
休息每分钟恢复1.5。使用固定精度和时间余量，重复推进不重复结算。
收到人类消息只归档；一次用户可见回复提交扣一次，分段、图片、TTS不额外扣。

唤醒方式：`chat` 私聊；`never` 聊天不可唤醒；`both` 私聊和原生群 @Bot。
群普通聊天、文本里伪造的 @、重复消息不累计唤醒尝试。沉睡不接受聊天叫醒。
精力≥10直接叫醒；不足10时首次抽两个0–9之和，大于8成功，否则失败。
此后每个新的有效尝试将保存值加1，大于8成功，醒来为恍惚，不增加精力。

唤醒回复轮默认3，窗口默认10分钟。每次真正开始生成占一轮，失败也计；
摘要阅读、日记、梦境、向量化和参与判定不计。第一次 Bot 回复提交到宿主输出
流程时开始绝对倒计时，后续回复不延长。轮数或窗口先耗尽即困；
最后一轮已准入的请求可以完成，沉睡与窗口到期仍优先拒绝。

日志来自真实状态事务：回复、疲劳、恢复、入睡、唤醒、手动、配置。
默认最近24小时；每桶保留极值，多状态所有者分别连线；表格可筛事件并分页。
旧数据没有日志时明确未采集。日志不保存聊天正文，保留7天、最多20000条。

## 晚安与醒后补课

“睡前晚安”独立控制正在对话的收尾。精力将跌破10或疲劳前提前量内，
优先把晚安并入当前回复；无当前回复时仅联系过去10分钟实际参与的原会话。
每周期、每会话最多一次，和其他发送共享总额度。
随机关闭使用本地休息文案；开启时单独生成一次，用收尾模型和共享模型预算。
等待后若人格、权限、新人消息或睡眠状态变化，取消旧结果。

补课单独归档原始消息，固定触发消息前的上界，晚到消息留给下一批。
采用45条、最多80条、60分钟分块；长正文按预算拆片，保留尾部。
成功阅读块有持久回执，失败保留未读；正常回复提交标记原消息已处理。
摘要只是导航，模型实际分片阅读原文。
可关闭历史补答并保留阅读；开启时每次唤醒最多3次补答生成，跨批次和重启共用额度。
补答与主回复共同消耗唤醒轮数，未知发送不自动重试或假称已送达。

## 日记、梦境和记忆

日记由 Bot 第一人称围绕授权素材发挥，程序固定添加日期、时区、住所城市、
该日期天气。城市未填显示未配置；天气失败显示未获取，不猜城市或拿今天补昨天。
天气没有素材时不会单独触发空日记。梦境保持想象标识，与日记分开查看。
打开私人正文可置顶或取消置顶，填写原因后保存。操作使用这篇记录的真实来源，
不调用模型；置顶冻结梦境当前清晰度，不能恢复已忘细节。取消置顶仍按原创建日期
计龄，可能立即过期。记录已变化时返回409，刷新后人工复核。

开启 LivingMemory 接入时仅调用公开门面，用当前真实事件查询，并在使用前复核；
授权不可用返回空，不读取私有引擎或回退本地库。
关闭接入时使用本地向量接口，选择 AstrBot 原生 DashScope/OpenAI 向量 Provider；
缺模型或超时返回空。自动收录只接收已经持久接受的人类消息和一次 Bot 提交记录，
不在正常回复路径等待向量请求。默认最多10000条、30天。
换模型使用新索引命名空间，不跨维度检索，不延长正文寿命；
删除、清空、停用和迟到请求均有代际校验。旧显式 local_lite 记录保持只读及原期限。

日记、梦、补课、晚安分别选择模型，空值沿用默认聊天模型；
共用队列、并发、每日次数与 Token 预算，不新增额度池。
向量调用复用原生 Provider 凭据，不另填密钥。

## 管理与协作

页面写操作要求当前 Dashboard 管理身份；资源 token、OAuth token、`admin=true`
不构成授权。认证失效清空私人视图，配置和关系写入不自动重试。
原生配置一次保存，版本冲突保留草稿供人工复核。

`le_wake` 仅已认证宿主管理员可用，前缀由 AstrBot 设置决定。
规则状态由插件补充，主回复仍归原生回复流程；活动状态下先缓冲回复，
让最终来源、记忆和睡眠检查在输出前执行。宿主提交不是平台送达，
bool/after-sent 不伪造回执，未知写入不重发。
原生 Live 模式强制流式且缺少这一提交接点，活动模式下拒绝该请求。

实现接点见 [状态](internal-state-contract.md)、[回复与补课](internal-reply-contract.md)、
[管理 API](internal-console-contract.md)、[记忆与模型](internal-memory-contract.md)。
兼容范围和实测限制见 [兼容矩阵](compatibility.md)。

# 配置参考

适用 LivingEmotion 0.11.2；2026-11-27依据公开 schema、保存校验和实际 Console DTO 核对。
维护者修改配置、范围或帮助文案时同步生成本表，每次提交运行 `python scripts/check_docs.py`。
全部功能开关和参数均逐项列出；使用操作见[使用手册](user-guide.md)，原理见[技术说明](technical-guide.md)。

功能归属、依赖与插件重叠见[功能边界](feature-boundaries.md)；本表只列字段、默认值和保存范围。

## 保存与生效

在插件页面 `livingemotion → 设置` 修改，统一保存。原生 AstrBot 配置页可编辑同一份配置。
默认值仅用于新安装或缺失键；不覆盖已有显式值。设置是平铺字段，分区只帮助导航。
页面刷新保留草稿；保存要求当前配置版本，冲突时重新读取再核对，失败不会落下半份设置。
模型凭据在 AstrBot Provider 管理；这里保存模型 ID。聊天模型与 embedding 不可互换。

作息时间按 IANA 时区解释；时区留空不启动自动 v2 作息。名单只匹配已有真实来源，
手填 QQ 号不会创建发送路由。开关开启后仍需满足本项说明中的身份、预算与条件。
数值范围为保存约束；字段名中的 `model_input_tokens` 为兼容名称，实际按UTF-8字节预算。
正文、模型预算、生成次数和平台送达是不同口径。

## 所有公开配置项

以下部分由 `scripts/check_docs.py --write` 从 schema、实际页面 DTO 和同源帮助生成。
长提示词使用完整默认值，避免把省略文案误认为可以写入配置的内容。

| `provider_id`<br>`""` | 设置 → 快速开始<br>文字 / 标识；具体限制见说明 | 各后台生成任务默认使用的聊天模型。 从 AstrBot 已配置的模型中选择；留空跟随会话模型。情绪细化使用此默认模型；日记、梦境、主动聊天、醒后补答和晚安等任务可用各自专用模型覆盖此默认值。 例：设置通用后台模型，再按需为日记或梦境单独选模型。 |
| `fallback_provider_id`<br>`""` | 设置 → 快速开始<br>文字 / 标识；具体限制见说明 | 请求发出前可使用的备用模型。 只在尚未发出请求时回退；超时或结果未知的请求不会自动重发，避免重复费用和行为。 例：主模型暂不可用时，选择已配置的备用聊天模型。 |

### 情绪

| 配置项 / 默认值 | 设置位置与范围 | 作用、开启关闭效果和例子 |
| --- | --- | --- |
| `emotion_model_enabled`<br>`false` | 设置 → 情绪<br>独立开关 | 允许模型辅助细化情绪。 在「设置 → 情绪」开启并选择模型；关闭保留本地规则。开启后四维细化按间隔调用，同时开启对象情绪时，冷却期间可补一次对象分析，共用全局每日预算。 例：需要委屈、受伤、害羞理解语气：同时开启这两个开关。 |
| `context_emotions_enabled`<br>`false` | 设置 → 情绪<br>独立开关 | 工作模式为「参与表达与行动」时按聊天对象记录委屈、受伤和害羞，并用于回复。 在「设置 → 情绪」开启并保存；仅观察模式不新增这三项采集，在「设置 → 快速开始」将「工作模式」改为「参与表达与行动」后生效。到 TA 页选择具体会话查看。关闭后停止更新和表达。同页开启模型细化后，LLM按最近对话、语气和已有情绪判断；本轮分析复用，冷却期间补一次对象分析，共用每日额度，回复前最多等待1秒；超时不取消，分析在后台完成并写回，下一次回复和TA页生效。模型不可用只保留历史衰减；关闭模型细化时兼容本地规则，不具备语义理解。害羞需友好关系，并尊重关系说明中的边界。 例：帮助被认可后又被否认可产生委屈；直接贬低可产生受伤；亲密关注可产生害羞。 |
| `context_emotion_shadow_enabled`<br>`false` | 设置 → 情绪<br>独立开关 | 对照新旧对象情绪判定，只记录差异。 在「设置 → 情绪」开启并保存，需同时开启对象情绪和模型分析。后台额外调用每个进程连续24小时最多12次；只在 AstrBot 日志记录差异，不改情绪、不影响回复上下文。关闭即停止额外调用。 例：在 AstrBot 日志搜索 [LE-emotion-shadow]。 |
| `scheduler_seconds`<br>`60` | 设置 → 情绪<br>1–3600，整数，秒 | 后台评估任务的间隔秒数。 范围1–3600；唤醒调度检查，不代表每轮都会调用模型或发送消息。 例：60表示每分钟评估一次；无需为随机主动行为改成很小的值。 |
| `model_concurrency`<br>`1` | 设置 → 情绪<br>1–8，整数，次 | 后台模型任务同时执行的上限。 范围1–8；只限制本插件任务，与AstrBot普通聊天并发配置分开。 例：1适合轻量部署；2允许两个后台任务并行。 |
| `queue_size`<br>`100` | 设置 → 情绪<br>1–1000，整数，次 | 等待执行的后台任务队列容量。 范围1–1000；队列有界，容量不是每日调用额度。 例：100表示最多排队100个任务。 |
| `model_daily_limit`<br>`48` | 设置 → 情绪<br>正整数，次 | 每天后台模型调用的总预算。 正整数次；跨情绪、日记、梦境和行为共用，预留后的失败尝试也计入。 例：48表示每天最多预留48次本插件后台调用。 |
| `emotion_interval_seconds`<br>`600` | 设置 → 情绪<br>正整数，秒 | 同一范围四维情绪分析的最小间隔。 单位秒，控制四维模型细化频率；开启对象情绪后，冷却期间可补一次对象语义分析，仍需预算。静默时段不调用模型，三项对象情绪只保留历史衰减。 例：600表示四维细化至少隔10分钟，对象情绪可随本轮对话变化。 |
| `emotion_quiet_start_hour`<br>`3` | 设置 → 情绪<br>0–23，整数，时 | 情绪静默时段的开始小时。 按本地时区24小时制填写0–23；与结束小时相同表示不启用静默。静默只跳过模型分析，本地规则仍随聊天生效。 例：3表示03:00起不调用模型；想连凌晨也分析就与结束设为同一小时。 |
| `emotion_quiet_end_hour`<br>`8` | 设置 → 情绪<br>0–23，整数，时 | 情绪静默时段的结束小时。 按本地时区24小时制填写0–23，结束小时本身恢复分析。开始大于结束表示跨午夜。 例：8表示08:00恢复模型分析；开始22、结束6表示22:00到次日06:00静默。 |
| `emotion_intensity`<br>`"normal"` | 设置 → 情绪<br>gentle / normal / intense | 情绪起伏的三档强度。 只放大单次情绪增量与同类刺激的累计上限，不改半衰期和衰减速度；数值越大，回复时情绪变化越明显。 例：平常为推荐档；嫌情绪变化太快要选保守，嫌太平淡选激进。改完在设置页保存即可生效。 |
| `model_input_tokens`<br>`32768` | 设置 → 情绪<br>1–32768，整数，Token | 每次后台模型任务的输入预算。 历史字段名保留；实际按完整请求UTF-8字节上界估计，范围1–32768，不是账单Token。 例：中文通常占多个字节，不能把此值当作可输入字符数。 |
| `model_output_tokens`<br>`1024` | 设置 → 情绪<br>1–8192，整数，Token | 普通后台任务的输出Token上限。 范围1–8192；日记/梦境独立使用8192 Token，正文最多2000字；路由上游输出限制仍生效。 例：1024控制普通后台任务，不限制日记和梦境正文。 |
| `model_timeout_seconds`<br>`30` | 设置 → 情绪<br>1–120，整数，秒 | 后台模型任务的超时时间。 范围1–120秒；超时不证明上游没有执行，结果未知时不会自动重复发送。 例：30秒适合通常响应较快的模型；较慢模型可填60。 |
| `emotion_provider_id`<br>`""` | 设置 → 情绪<br>文字 / 标识；具体限制见说明 | 情绪精炼专用模型。 在「设置 → 情绪」选择并保存；留空沿用默认模型或当前聊天模型。选小模型可缩短每轮情绪分析的耗时；该模型连续失败3次后10分钟内改走LE默认模型链，之后自动恢复。 例：填 Qwen/Qwen3-8B 这类小模型，加快每轮情绪分析。 |
| `weather_factor_enabled`<br>`true` | 设置 → 情绪<br>独立开关 | 天气作为本地权重因子影响情绪回落目标。 本地定时轮询实况天气，不经大模型；只调整四维的回落目标，不改当前值、不落库，也不参与六情绪计算。关闭后天气只作为日记与梦境的背景文字。 例：需要TA的心情随晴雨缓慢变化：开启；只想保留天气文字：关闭。 |
| `weather_poll_seconds`<br>`14400` | 设置 → 情绪<br>300–21600，整数，秒 | 天气轮询间隔。 保存范围300–21600秒，默认14400即4小时；受抓取窗口限制，失败从300秒起退避。 例：默认06:00–次日01:00窗口最多5次计划评估，不是实测请求数。 |
| `weather_transition_seconds`<br>`900` | 设置 → 情绪<br>0–7200，整数，秒 | 天气权重切换的过渡时间。 范围0–7200秒；天气从雨转晴时新权重按指数曲线逼近，避免整点跳变。0表示立即生效。 例：900表示约15分钟平滑过渡。 |
| `weather_weight_scale`<br>`1.0` | 设置 → 情绪<br>0–3，步进0.1，次 | 天气权重总倍率。 范围0–3；1.0为标定值，0等于关闭影响（等价于 enabled=false），2.0加倍。只缩放四维回落目标的偏移，不改半衰期。 例：觉得雨天的情绪影响太弱：调到1.5。 |
| `weather_stale_seconds`<br>`7200` | 设置 → 情绪<br>300–86400，整数，秒 | 天气权重的缓存保鲜期。 范围300–86400秒；超过该时长没有成功取到天气，权重回落到中性，避免用两天前的晴天影响今天的情绪。 例：7200表示两小时后失效。 |
| `weather_forecast_days`<br>`7` | 设置 → 情绪<br>1–16，整数，天 | 一次预取的预报天数。 范围1–16天；接口一次请求就能返回多天，实况请求失败时直接改用当天预报，不必回落到中性权重。 例：7表示一次拿七天。 |
| `weather_forecast_refresh_seconds`<br>`21600` | 设置 → 情绪<br>600–86400，整数，秒 | 预报表刷新周期。 范围600–86400秒，默认21600即6小时一次；预报比实况稳定，不会天天失败。 例：21600一天最多刷新4次。 |
| `weather_window_start_hour`<br>`6` | 设置 → 情绪<br>0–23，整数，时 | 天气抓取窗口的起点整点。 本地时区，范围0–23；窗口外完全不发请求，夜间不打扰接口。 例：填6表示06:00开始。 |
| `weather_window_end_hour`<br>`1` | 设置 → 情绪<br>0–23，整数，时 | 天气抓取窗口的终点整点。 本地时区，范围0–23，可跨夜；与起点相同表示全天抓取。 例：填1表示次日01:00结束。 |
| `weather_degrade_after_failures`<br>`3` | 设置 → 情绪<br>1–10，整数，次 | 连续失败多少次后降级。 范围1–10；降级后停止高频抓取，改为每天窗口起点只刷一次日粒度预报，用它保底，不再反复撞接口。 例：填3表示连挂三次就改每日一次。 |
| `weather_recover_after_successes`<br>`2` | 设置 → 情绪<br>1–7，整数，次 | 连续多少次日粒度成功才恢复高频。 范围1–7；默认2天，避免刚恢复又撞墙。 例：填2表示连续两天抓到预报后再试高频。 |

## 兼容字段与升级

旧字段 `memory_mode`、`memory_export`、`night_enabled`、`night_block_chat`、
`sleep_at`、`night_policy_version`、`autonomy_scopes`、`night_schedule_enabled`
只供兼容读取，不在公开页面作为独立权限。显式 `allow_sleep` 优先。
只有原始映射缺少 `allow_sleep` 时，才继承旧作息许可。
旧 `allow_sleep=true / night_schedule_enabled=false` 组合现在按总开关运行自动作息。

AstrBot可能在插件构造前按schema补默认和清理退役键。非常旧的文件缺少allow_sleep时，
升级前备份并显式保存睡眠许可，不能仅依赖旧键自动迁移。
关闭总开关立即清醒/100%；再次开启从新计时起点运行，不补扣关闭期间。
`promise_max_depth` 和 `promise_advance_limit` 是兼容保存值；当前执行器不读取，
提前上限实际固定3次。`promise_max_active` 已参与原子准入，等待调整和结果未知仍占名额。

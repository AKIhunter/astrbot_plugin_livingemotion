# 开心 5 分钟窗口（0.4.0）

每条消息仍即时处理。最近 300 秒内，事件刺激造成的派生开心 `joy`
累计上涨最多 5 个百分点、下降最多 10 个百分点；正负额度独立，
不会通过先涨后跌互相抵消额度。

## 方向与口径

| 当前事件 | 开心刺激变化 |
| --- | --- |
| 明确针对 Bot 的正向言行 | 可以上涨，受 +5 个百分点剩余额度限制 |
| 明确针对 Bot 的负向言行，如“给你降智” | 可以下降，受 −10 个百分点剩余额度限制 |
| 普通互动、中性纠错或纯事实说明 | 保持事件刺激前的开心 |
| 群聊对象不明、明确指向他人 | 不猜测 Bot 应该因此开心或难过 |

私聊默认有直接指向依据；原生消息明确指向他人时优先排除。
群聊需明确 At Bot 或回复 Bot，单独一句“你”不够。
本地文本证据识别是保守规则，不能保证理解全部讽刺、隐喻和复杂转述。

内部计算 `joy = max(0, pleasure) × (1 − 0.35 × stress)`。
限幅作用在这个派生结果上，避免“纠错使压力下降”间接导致开心大涨；
必要时反算愉悦，并在饱和边界收窄压力增量，其余维度继续按规则变化。
情绪强度仍影响原四维规则增量，但不会把这份开心预算扩大。

这里限制的是**事件刺激增量**。自然衰减先结算，再以衰减后的状态为参照；
页面天气加成另行叠加。因此两次页面读数的总差不保证恰好落在 +5/−10 内，
中性消息也不等于数值永远不随时间变化。

## 实现与成本

`domain/emotion.py` 的 `_limit_joy()` 与 `apply_emotion()` 统一处理方向和预算。
模型细化重算当前事件时使用相同路径，通过本轮快照替换与 CAS 写回，
不会再追加第二笔刺激。审计规则版本为 `emotion-3`。

窗口保存在状态所有者的 `runtime.joy_window`，只保存时间和实际增量。
每次事件清理过期项，最多 192 条；满容量时拒绝新增刺激，
保留未过期记录防止释放额度。重启后仍沿用窗口，旧状态缺省为空。
迟到事件先按时间衰减，不会重新获得完整单次变化。

这不是每 5 分钟启动一次模型或扫描全部会话。只在现有事件处理时检查
有上界的小列表，不新增模型请求、定时器或数据库 schema 迁移。
未提供性能实测倍率，不据此声称 CPU 消耗为零。

## 离线验证

```bash
python -m pytest tests/domain/test_joy_window.py \
  tests/integration/test_joy_window_runtime.py -q
```

覆盖方向、中性压力补偿、正负独立预算、恰好 300 秒到期、迟到事件、
模型替换、重启、旧状态、容量上限及时间乱序。测试使用虚拟时间与临时 SQLite，
隔离 Provider 和平台，不产生收费模型请求或真实消息。

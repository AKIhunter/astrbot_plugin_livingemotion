# TA 的此刻心绪

TA 页左侧卡片与右侧情绪球卡片在宽屏下等高。情绪图片下方显示「此刻心绪」：一句 12–20 个汉字的第一人称心理感受，标点不计入字数。窄屏按阅读顺序上下排版。

## 生成与展示

插件启用且处于 active 模式时，现有调度器检查当前配置的人格。首次检查生成一句，之后每隔 43,200 秒生成一次。生成使用当前人格风格、当下六维情绪（含当天天气加成）、真实的本地聊天经历和已授权的 LivingMemory 检索材料。没有记忆时只描述当前感受，不编造经历。

优先沿用已配置的日记模型，其次是梦境模型，然后使用通用聊天模型与备用模型；全部未配置时，只能从已有真实会话获取当前聊天模型。每次生成遵守现有模型输入上限、输出上限、每日总预算和并发限制。输出预算最多 256 token，不豁免每日预算。

短句只进入管理员控制台，不主动发送消息，不写回记忆，也不额外注入聊天回复。天气仍同时作用于既有日常情绪和梦境逻辑。

## 授权与持久化

- 本地素材限当前实例、当前人格的合法私聊和群聊；不读取公共评论来源。
- LivingMemory 必须通过 MemoryGateway，并附带原始宿主事件。缺少原始事件或 memory_read 关闭时不检索，不构造发送路由。
- 调用模型之前、保存之前重新检查人格、配置、模型指纹、来源代次和外部材料授权。
- 短句及生成状态写入 SQLite 的 runtime_meta，使用 `console.feeling.v1:` 加实例/人格摘要作为键。无需表结构迁移。
- 只保存短句、时间、运行身份、状态和来源 scope key，不保存提示词或原始记忆正文。
- `console/state` 的 feeling 只含 text、generated_at、next_due、status。读页面不会触发模型生成。

## 周期与失败处理

事务先占领周期，再提交受预算控制的模型请求。同一周期重复调度不会重复调用。失败、未知结果和关闭过程中断都保留原来的有效短句；同一周期不自动重试。重启错过多个周期，只补写一次，并从本次尝试起安排下一次 12 小时周期。

任务设整体截止时间。进程退出遗留的 running 记录超过截止时间后显示 unknown，旧任务晚到的结果不能覆盖新周期。暂停或 observe_only 时不生成。

清除任一关联来源时，在清除事务中同步清空派生短句并取消正在生成的结果，保留周期墓碑，防止清除操作导致重复付费。

## 验证入口

```sh
.venv/bin/python -m pytest tests/experience/test_feeling.py -q
node tests/ui/feeling-browser.test.mjs
```

后端测试使用真实 SQLite、真实后台队列和合法来源格式；模型为可控合成模型。浏览器测试验证等高布局、窄屏无溢出、明暗主题、短句渲染，以及刷新页面没有写请求。

## 页面按两张标注图调整

| 类型 | 左侧大字 | 左侧小字 | 右侧 |
| --- | --- | --- | --- |
| 日记 | 保留日期 | 星期几，保留天气 | 模型生成的一句话标题 |

标题最多 80 字符，缺失或非法标题不阻止正文保存。旧日记没有标题就留空；旧梦境没有情绪快照就留空，不用当前情绪补造历史。梦境情绪随记录保存，之后情绪变化不会改写该记录。

页面继续自动刷新。自动任务的结果单独展示，手动生成的状态仍保留；自动失败能看到原因和 HTTP 状态。

## 生成行为

1. 正文上限为 **2000 字符**，中文、标点、空格和换行都按字符计数。程序添加的日期、城市、天气，以及独立标题不占正文额度。2000 字正文可保存，2001 字拒绝保存。
2. 日记、梦境独立申请 **8192 输出 Token**，普通任务继续使用原 `model_output_tokens`。删除“UTF-8 字节数超过 Token 预算就拒绝正文”的错误判断，保留响应大小保护。Token 是请求预算，2000 字符是正文验收标准，两者分开。
3. 正文生成前，通过实际 Provider 的客户端执行 `GET /models`，只有 HTTP 200 才继续。SDK 不重试，预检最长 5 秒。Pinned router 检查所选子上游，不检查路由总入口或其他上游。
4. 自动预检失败不预留生成额度、不调用生成模型；记录安全的原因码与 HTTP 状态。手动失败保留已有正文。日志不包含密钥或上游异常原文。
5. 自动日记、梦境的生成等待至少 90 秒，工作队列另留 15 秒用于收尾；普通后台任务超时配置不变。
6. 正常状态刷新不再让已经读取的情绪素材失效。仅信任本任务亲自读取的状态快照；清空、身份变化、授权撤销和素材过期仍会拦截保存。
7. 开启“补写昨天”时，调度器分别处理昨天与今天，最多回补昨天一天。昨天的窗口不受今天的新消息水位影响；已有日记或手动档案不会被自动覆盖。
8. 梦境“成功篇数”与“调用尝试次数”分别计数。每夜最多尝试 `dream_per_night × 3` 次，成功篇数仍受 `dream_per_night` 限制。明确失败可以在后续调度重试；正在生成或结果不明时暂停重复调用。
9. 页面读取睡眠状态只做显示投影，不写入睡眠状态、不重新抽取随机值。实际状态推进由运行任务负责。

`GET /models` 的 HTTP 200 仅证明该接口可连接、鉴权通过，不能保证随后正文生成一定成功。路由及上游自身的输出上限、超时、重试策略仍然生效，例如 router 的较小输出上限仍可限制正文；本次没有修改路由插件或线上配置。

# 好感度计分 V2（0.4.0）

界面为 0–100 分；内部原始分数除以 10 后显示。每条有效消息的最终非零增减为 0.5–1 分。
此方案使用 `relationship-3` 运行时版本，避免与原有 `relationship-2` 审计记录混淆。

| 当前直接言行 | 显示增减 |
|---|---:|
| 主体不明、纯事实、普通交流、他人情绪、引用和否定 | 0 |
| 夸奖、感谢、真诚道歉、有依据纠错、有用教导、尊重边界 | +0.5 |
| 实质关怀、主动帮助、履行承诺 | +1 |
| 轻度冒犯、冲突、侵犯边界 | −0.5 |
| 辱骂、威胁、蓄意违约 | −1 |

## 调用链

1. `adapters/astrbot.py` 从原生 At 的 `qq`、Reply 的 `sender_id` 读取对象。
   私聊可提供直接指向依据。群内须明确指向 bot；多个对象或明确指向他人时不计分。
   群聊里的“你”不能单独证明对象。
2. `domain/appraisal.py` 剔除引用，区分直接表达、转述和否定，识别当前证据。
   “对不起，我不该骂你”识别为道歉，既往冒犯不作为当前辱骂。
3. `domain/relationship.py` 对关系证据单独计分，不使用普通互动和用户自身情绪兜底。
   同向信号取最强档位；负向言行优先。置信度低于 0.65 不计分，置信度不乘分值。
4. 冻结、管理员特殊关系、去重、时序和来源保护保持原有约束。
   日预算正负独立，各为内部 24（显示 2.4）分。
   单事件上限由内部 6 调整为 10；同类窗口预算由 9 调整为 10，让明确帮助可完整加 1 分。
   同类窗口仍为 300 秒，最多 3 次；余量不足 0.5 时不产生小尾数。
   没有计分的普通/主体不明消息保留去重记录，不占后来真实关系证据的计分次数。
5. 按事件上限、日预算、同类预算和分数空间限制最终写回。
   普通关系上限仍为 99 分。余量为 0.5–1 时可以写回该范围内的实际变化；
   小于 0.5 时保持不变，且不消耗计分预算。
   存量分数可能带小数，写回范围检查允许 1e-9 原始分以内的浮点舍入误差。
6. `runtime/projector.py` 将快照、预算、贡献和 trace 原子写回。
   `runtime/refinement.py` 使用相同计分函数，从本轮原始快照重算并通过 CAS 替换本轮记录，
   不追加第二份分数。模型证据须逐字来自当前非引用文本，并通过本地言行校验。

## 可追踪字段

关系 trace 保留 `rule_version`、`before`、`after`、`charged`；
新增 `subject`、`signals`、`selected_signals`、`delta_display`、`reason_codes`。
冻结等提前返回的记录用原因码说明保护，不假定已经核实对象。

## 存量兼容

不调整数据库 schema、不批量重写旧分数，不清空旧预算和去重记录。
现有内部数值、关系阶段、人工编辑 0.1 步进、冻结和特殊关系保留。
旧日预算和同类预算已消耗的额度继续参与限制。
旧 trace 保留原运行时版本；新处理的事件记录 `relationship-3`。
设置 schema 无新增项，界面补充自动增减说明，现有自动刷新继续生效。

## 验证边界

本次是离线代码与状态验证，使用真实 Application、SQLite 和原生消息桥接，以及虚拟时间。
模型边界不联网，不生成 assistant 回复，不向 QQ 等平台发送消息。
主体/证据识别仍是保守的文本规则：未命中表达不会猜测补分。
纠错规则要求当前文字包含具体纠错和依据；离线输入的外部“原文”未经外部事实核验，
本次结果不证明所有自然语言纠错、讽刺、隐含对象和复杂转述均可识别。
情绪的其他维度仍可随互动变化；开心另受方向校验与 300 秒预算保护，
中性或对象不明的互动不额外增加开心。好感度与情绪分别计量，
见[开心窗口](joy-window.md)。

验收测试：`tests/integration/test_relationship_v2.py`；
完整发布验证与同环境基线比较随 GitHub Release 说明记录，不包含私人逐轮聊天数据。

# 承诺兑现的上下文、多气泡与片段缓存

> 适用版本 0.3.2 及以上。配套改动见 `runtime/promise_context.py`、
> `runtime/promise_service.py`、`storage/promise_store.py`。
> 本文同时给出**第 4 点（主动聊天只留一个子系统）**的改造范围。

## 0. 一句话

承诺不是"到点发一句话"，而是**替未来的自己保存一份当时语境**：
建立时写概要并预取记忆，到点读快照生成一到三句、按行拆气泡，
兑现后把片段留一天供追问命中，过期释放回正常检索。

## 1. 三条断裂

旧实现只存了 `description`（"发一张自拍"）。到点时有三个断点：

| 断点 | 现象 | 根因 |
| --- | --- | --- |
| 语境断 | 生成出来像客服："好的，现在发给您" | 只有一句描述，没有"谁、为什么、当时怎么说的" |
| 召回断 | 外部记忆后端返回空 | `LivingMemory` 只认**真实事件**授权；到点没有 event |
| 追问断 | 用户问"你刚发的那张呢"，bot 重新检索甚至答不上 | 兑现那句话虽然写了记忆，但没有"就地问"的短路径 |

## 2. 第 4 点：主动聊天只留一个子系统

### 2.1 问题

宿主自带一条「主动找主人聊话题」的 cron（默认 10:30 / 15:30 / 20:30），
LivingEmotion 还有一套 90–240 分钟的随机主动行为。两套同时开：

- 同一时段各说一次，用户看到"今天怎么连着来两条"；
- 两条都写记忆，画像把同一天算成两次主动接触；
- 额度分别统计，面板上的数字对不上。

### 2.2 改造范围（只做这四件事）

| # | 做什么 | 不做什么 |
| --- | --- | --- |
| 1 | **只读探测**宿主 `data/data_v4.db` 的 `cron_jobs`，按措辞识别主动聊天任务 | 不写宿主库、不改 `enabled`、不删 job |
| 2 | 探测到就让行：`maybe_proact` 直接返回，不发随机主动行为 | 不拦承诺兑现、不拦睡前晚安、不拦醒后补课 |
| 3 | 「功能耦合」面板加一行「宿主主动聊天」，给出条数与让行状态 | 不把宿主任务搬到 LE 面板里管理 |
| 4 | 配置 `proactive_native_yield`（默认开），关掉即恢复旧行为 | 不做"自动删除宿主任务"这种不可逆操作 |

### 2.3 交互细节

- **识别口径**：`name` 或 `note` 含「主动找 / 主动聊 / 主动问候 / 聊话题 / 找主人 /
  主动搭话 / 主动说话」之一，且 `enabled` 不为 0。只认明确措辞，
  避免把「晚安」「日记」算进来导致永久让行。
- **刷新节奏**：5 分钟一次（`probe_once` 结果缓存）；首次进入主动行为时读一次。
- **用户关闭宿主任务后**：最长 5 分钟内面板变「未检测到」，LE 自动接管，
  不需要改任何开关，也不需要重启。
- **用户想两边都留**：把 `proactive_native_yield` 关掉即可，面板显示
  「让行已手动关闭」，但两条都发的风险由用户承担。
- **独立部署（没有宿主 data 目录）**：按"未检测到"处理，行为与旧版一致。

## 3. 承诺记忆链路

### 3.1 建立承诺（有真实 event 的唯一时机）

```
on_reply_submitted
  → 取出本轮用户原话 + bot 回复正文
  → 从 body_window 取最近 8 条（含"反问—确认"那几轮）
  → build_summary(): 压成 [时间] 谁：什么
  → build_query(): 保留人类原话，不抽关键词
  → promises.create(..., context_summary=summary)
  → prefetch_promise_memory(event=真实事件)
       → memory.recall(query=原话+描述)
       → 材料写入 promise_traces(kind='prefetch')
```

**为什么召回必须前置**：外部记忆后端的授权凭证是"当前这条真实消息"。
承诺到期可能隔几十分钟、跨一次重启，那时 `bridge` 里连 source 都没有，
后端只会返回 `external_background_authorization_unsupported`。
等到点再召回，注定是空。所以在"消息刚提交、event 还在"的这一刻取一次。

**优先复用本轮对话的召回结果**：`on_llm_request` 一定握着用户消息事件，
那一轮如果已经召回出材料，会按会话存十分钟（`_memory_leases`）。
承诺落库时先用这份，零额外检索，也不用赌回复提交事件能不能通过外部授权；
只有没开记忆读取、或本轮没召回出东西时，才回退到用当前事件再检索一次。

### 3.2 到点兑现

```
tick 15s → due() → move(running)
  → 读 promise_traces(kind='prefetch')：概要 + 材料快照
  → 若后端 background_recall=true（本地向量/轻量）：
       按概要 + 描述再召回一次，合并去重
  → compose_promise(): 人格 + 承诺 + 概要 + 材料
       system: 一到三句、一句话一行、最多三行、不复述、不提记忆
  → clean_delivery(): 保留标点与换行，只清 markdown/列表符号
  → send_promise_notice(keep_stops=True)
  → 发送层按换行拆气泡（最多 6 条，间隔 0.35s）
  → move(sent) + set_delivery(text) + put_trace(kind='delivery', ttl=24h)
```

**断句权归模型**：旧路径统一套 `strip_stops`，把逗号句号换成空格，
再把整段塞进一个气泡——读起来像电报。现在只有"取消成功/清单"这类
固定文案继续走 `strip_stops`；兑现正文走 `clean_delivery`。

### 3.3 追问命中片段缓存

```
on_llm_request
  → _recent_promise_trace(scope, 当前消息)
       命中条件：TTL 内 + （回指词 或 与片段正文有连续两字重叠）
  → 命中：注入 PROMISE_TRACE_SUFFIX（概要 + 当时那句话 + 材料），
           **不再调用 memory.recall**
  → 未命中：原来的向量检索路径不变
```

- 缓存是 LE 自己写的本地数据（同 `scope_key`、带 TTL），
  不依赖外部记忆的读取授权，所以放在 `memory_read` 判断之前。
- 相关性判据保守：宁可多一次向量检索，也不把无关片段硬塞给模型。
- TTL 默认 24 小时（`promise_trace_ttl_hours`），`purge_traces` 在每轮 tick 清理。
  过期后追问回到正常检索，不会长期占着旧语境。

## 4. 数据结构

### promises（新增两列）

| 列 | 用途 |
| --- | --- |
| `context_summary` | 建立时的对话概要（≤1200 字），到期生成与面板排错共用 |
| `delivered_text` | 真正发出的文本（多气泡以 `\n` 连接） |

### promise_traces（新表）

| 列 | 用途 |
| --- | --- |
| `trace_id` | `{promise_id}:{kind}`，同承诺同类型覆盖，不堆积 |
| `kind` | `prefetch`（建立时）/ `delivery`（兑现时） |
| `summary` | 当时的对话概要 |
| `materials_json` | 召回材料 `[{kind,text,occurred_at}]` |
| `reply_text` | 兑现正文（prefetch 时为空） |
| `expires_at` | 到期即释放 |

## 5. 交互细节对照

| 场景 | 用户看到 | 系统动作 |
| --- | --- | --- |
| 用户说"想看大美女自拍"，未指向 bot | bot 反问"谁呀？我吗？" | 不建承诺（信息不足） |
| 用户补充"你呀" | bot 说"那我晚点给你发" | 建承诺 + 写概要 + 预取材料 |
| 到点 | 1–3 条气泡，有标点、有称呼、像接着聊 | 读快照 → 生成 → 拆气泡 → 写缓存 |
| 用户追问"刚才那张呢" | 直接接着答，不重新检索 | 命中片段缓存 |
| 用户隔天再问 | 正常回答或说记不清 | 缓存已释放，走向量检索 |
| 宿主主动聊天开着 | 只有宿主那条 | LE 让行，面板标注 |

## 6. 验收标准

| # | 操作 | 期望 |
| --- | --- | --- |
| 1 | 走完"反问 → 确认 → 承诺" | `promises.context_summary` 含三轮对话，`promise_traces` 有 `prefetch` 行 |
| 2 | 等到点 | 日志 `承诺已发出 ... 气泡=N`；用户收到 N 条独立气泡；正文有标点 |
| 3 | 追问"你刚才发的那张" | 日志 `追问命中片段缓存`；不出现 `memory.recall` 检索日志 |
| 4 | 把 `promise_trace_ttl_hours` 设为 1，隔 2 小时再问 | 缓存已清，走正常检索 |
| 5 | 宿主存在主动聊天 job | 「功能耦合」出现「宿主主动聊天 · 已连接」；随机主动行为不发 |
| 6 | 停掉宿主那条 job | 5 分钟内面板变「未检测到」，随机主动行为恢复 |

---

**一句话总结**：概要是"给未来的自己留的便签"，预取是"趁还能进门先把资料拿出来"，
片段缓存是"刚说完的话先别急着归档"。三者缺一，承诺就退化成定时播报。

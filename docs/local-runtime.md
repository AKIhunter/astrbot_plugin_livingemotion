# 独立运行与升级

开发者：[AKIhunter](https://github.com/AKIhunter)。

LivingEmotion 的情绪、人物关系、作息、精力、补课、主动机会和额度都由插件自己计算、
保存和校验。安装 AstrBot 并加载本插件即可使用本地规则情绪。
其他情感插件的安装或开关不会改变 LivingEmotion 的运行模式。

## “本地化”包含什么

| 项目 | 当前行为 |
| --- | --- |
| 运行模式 | 由自己的 `enabled`、`mode` 决定；`observe_only` 仍不注入或自主发送 |
| 情绪与关系 | 使用自身规则与 SQLite 状态，默认不需要模型 |
| 作息与补课 | 自身归档、固定读取上界、完整分块、回执与最多三次补答 |
| 自主行为 | 自身白名单、时区、冷却、配额、未回应退避及发送者校验 |
| 日记与梦境 | 自身素材与存储；生成仍需已配置的 AstrBot Provider |
| 旧库导入 | 不再提供导入、旧约束接管或消费者回退工具 |
| 页面 | 自有资源与本地依赖，状态自动刷新 |

“本地化”不表示把模型改成离线模型。主动聊天、补答、模型情绪、日记和梦境在开启后
仍可能调用你选择的 Provider；天气和显式开启的记忆接入也可访问外部服务。
未开启这些功能时，普通规则情绪不需要模型调用。

## 升级后怎么用

1. 升级前备份本插件代码、配置及 SQLite 一致快照；不要只复制正在使用的主数据库文件。
2. 按更新文件清单逐文件替换，并删除清单中已撤下的旧工具文件；不要整目录覆盖。
3. 应用或重载插件；服务器部署按运行环境重启 AstrBot。
4. 返回插件页面，确认人格、情绪、关系和设置能正常读取；模式与自己的设置一致。
5. 开启更多功能时，仍按[插件帮助手册](plugin-manual.md)逐项配置。

现有 LivingEmotion 数据库结构、配置和原生版本升级机制保留，不清空情绪、关系、
日记或梦境。历史参考及旧验收材料可在 Git 历史中查看，不作为当前能力证明。
从未导入旧数据的部署无需数据迁移；曾使用旧导入工具的部署，应先审查旧档案，
本版不再接管其旧额度或待执行状态，也不承诺继续运行旧数据。
来源类型为 `legacy_unknown` 的体验仍遵守原期限与七天硬上限，置顶不能延长。

## 可选协作

LivingHello 可以通过公开契约读取状态，补课耗时键为
`livingemotion:wake_prepare_seconds`；不会再写另一插件的计时键。
LivingMemory 与 BiliBot 仍是可选接点，不是核心运行依赖，具体接口见[协作说明](consumers.md)。

## 验收与回滚

开发回归使用合成 Provider、虚拟消息及隔离数据库；生产巡检只读取管理接口。
这些检查不等于真实模型效果或真实平台送达测试。

如果部署检查失败，使用本次备份的逐文件回滚脚本恢复代码，再重启并核对运行态。
业务配置和数据库保留当前值，不用旧整库覆盖新记录。

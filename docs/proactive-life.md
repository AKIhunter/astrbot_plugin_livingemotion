# 主动聊天：想起你时，自然开口

主动行为已接入 `Application.tick → maybe_proact → BehaviorService`，
可以在没有新消息触发的情况下生成并发送聊天。总开关默认关闭。
随机选择时机和动机使用本地规则，只有通过检查后的生成、可选记忆检索才会调用模型。

## 快速开始

打开 **设置 → 主动行为**：

1. 打开“允许主动找人”，在“主动行为范围”勾选允许联系的私聊或群聊。
2. 选择“主动节奏”和“主动聊天模型”。模型留空沿用当前聊天模型。
3. 按需调整随机等待时间与聊天结束后的安静时间。
4. 群聊还需打开“允许群聊主动行为”；配置本地时区。
5. 保存一次，之后自动等待。**主动行为**页面查看下次随机检查、最近动机、
   未回应次数和执行记录。全局视图没有发送目标，选择具体私聊/群聊查看节奏。

时间到达表示再次判断是否适合开口，不保证固定时刻发消息。
“仅模拟”只检查原有硬规则，不抽取或消耗随机机会，不检索记忆、不调用生成模型、不发送。
手动“生成并真实发送”是独立操作，仍受全部发送规则约束。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| 主动节奏 | 自然 | 轻柔 / 自然 / 活泼，影响愿意开口的概率 |
| 随机等待 | 90–240 分钟 | 每次机会后重新抽取，支持 1–10080 分钟 |
| 安静时间 | 20 分钟 | 最近人类消息或本插件参与后先留白；群聊按全群消息计算 |
| 分享心情 | 开 | 仅熟悉私聊可选；主动发送总开关仍须开启 |
| 每日主动额度 | 全局 6、每会话 2 | 包含实际预留后的失败、取消与未知结果 |
| 发送冷却 | 120 分钟 | 冷却内不会再发送 |
| 未回应上限 | 2 次 | 一次未回应先降低开口概率；达到上限停止，直到新的真实人类消息 |

## TA 会怎样找话题

| 动机 | 选择条件与表达 |
| --- | --- |
| 记忆回访 | 从已授权聊天/长期记忆找一件对方在意的事，温和问问后续 |
| 关心近况 | 关系越熟悉越容易出现；旧烦恼只作为历史，不假定现在仍然如此 |
| 轻松闲聊 | 从共同兴趣引出一个小问题，也可以分享一个想法 |
| 分享心情 | 私聊、好感原始值至少600（页面60）、证据完整，已知信任不低于0.55、已知边界小于0.5 |
| 久别问候 | 至少三天未收到当前会话消息，且好感至少200（页面20） |

相邻两次生成尽量不选同一动机。记忆锚点按机会轮换，保留最近8个素材来源哈希，
不在调度记录保存正文。轻松话题取1条素材，记忆回访最多2条。
全部候选都已用过且没有新材料时跳过，避免反复问同一件事。

生成输入包含当前人格、关系数值、Bot情绪数值和授权素材及原时间。
不包含其他会话的情绪原因、内部账号标识或提示词机制。
群聊不选择“分享心情”，不使用私聊素材。没有授权素材时不会编造共同经历。

表达要求为人格使用的语言，通常1–3句、最多一个容易回答的问题。
允许轻微主观心情，不要求对方安慰，不责怪失联，不催回复，不制造情感负担。
这些是生成约束；最终文案质量仍受所选模型影响，本地测试不代表真人语言质量评测。

## 运行和故障边界

| 项目 | 实现 |
| --- | --- |
| 时间基准 | 随机等待用UTC时间戳；活动时段、免打扰、每日额度按配置IANA时区 |
| 夏令时 | 相对等待不重复按墙上时间触发；当地时间只用于规则检查 |
| 防重与并发 | 每个实际会话只有一份调度状态；事务先消耗机会，再进入原有串行发送执行器 |
| 群聊对象 | 每群只取最近出现的有效来源账号，继续复核该账号、受众和实际路由 |
| 执行期限 | 每个机会最长120秒加模型超时；原有依赖、模型、发送各自限时 |
| 迟到和重启 | 超过允许迟到 `max(300秒, 2×调度间隔)` 的机会跳过，不补发；未过期等待不会重抽 |
| 中断与时间倒退 | 已运行机会超期、时间倒退都跳过并重新等待，不重放旧意图 |
| 可观测性 | 最近检查、开始/结束、结果、原因、下次时间、错过次数持久化；控制台健康项提示检查延迟或运行超期 |
| 配置变化与清空 | 重建等待，旧代际不得继续提交；序号保留，配置切回不会复用旧机会ID |

`BehaviorService` 默认评分门槛仍是0.35；应用层使用0.20，让已有真实互动的新关系
也能温和开口。评分不能绕过白名单、身份、受众、睡眠、精力、时段、额度或记忆授权。
小憩、恍惚、困、沉睡均不主动找人。关系在生成期间变得不适合分享心情时，
整段旧文案取消。

所有消息通过已有唯一发送端。发送前再次核对清空代际、最新人类消息、
人格、路由、受众、身份、睡眠及全部素材。结果未知不重试。
当前AstrBot发送API的bool/None不能证明送达，因此执行记录可能是
`unknown`；这是已提交但无法可靠确认，不是自动重发理由。

文件接点：
`domain/proactivity.py` 选动机和概率；
`storage/proactivity.py` 持久机会；
`runtime/proactivity.py` 驱动；
`runtime/materials.py` 选题；
`runtime/models.py` 生成；
`services/behavior.py` 最终发送守卫。

本功能的便携回归位于 `tests/behavior/test_opportunities.py`、
`tests/integration/test_proactive_runtime.py`；均使用真实临时SQLite及合成模型/发送桩。
本地实现不会变更现有生产运行模式，也不代表已部署。

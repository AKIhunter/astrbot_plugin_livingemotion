# 功能边界、依赖与插件重叠

适用 LivingEmotion 0.12.0，2026-11-28 依据 README、配置 schema、使用手册和运行代码核对。
本页回答三个问题：**这个功能做什么、什么时候该开、和另一个插件是否重复**。
字段默认值、位置和例子仍以[配置参考](config-reference.md)为准。

## 先看结论

- LivingEmotion 负责**角色状态与自主行为**：情绪、关系、作息/精力、主动聊天、承诺、日记/梦境、记忆提供者、风格摘要。
- LivingHello 负责**入站回复闸门、回复整理、图片理解与生图执行、发送回执**；LivingMemory 负责**长期记忆存储与召回**。
- 支持 LivingEmotion + LivingHello 同时安装；不要再装第二个「主动发送器」「情绪/好感度写入器」「长期记忆库」或「同一事项的生图执行器」。
- 安装不等于启用：对象情绪、情绪模型、随机主动、自动日记、梦境、长期记忆默认关闭；承诺和允许睡眠默认开启。`mode=observe_only` 只记录状态，不注入表达、不自主发送。

## 功能清单

| 功能 / 入口 | 作用 | 什么时候该用 | 依赖 | 明确不负责 |
| --- | --- | --- | --- | --- |
| 工作模式 `enabled` / `mode` | 启用生活状态；`active` 正常表达与自主行为，`observe_only` 只观察 | 先观察再上线；或让另一个插件负责表达时 | 无模型依赖 | 不改变宿主人格；不替代回复闸门 |
| 规则情绪 | 四维规则算出六项基础情绪，不需要模型 | 大多数场景默认可用 | 无模型依赖 | 不做语义理解；不等于模型判断 |
| 模型情绪细化 `emotion_model_enabled` | 模型按近期对话细化情绪 | 需要更细腻的情绪变化时 | 聊天模型、每日预算 | 不保证模型判断正确；不改变事实依据 |
| 对象情绪 `context_emotions_enabled` / `context_emotions_dimension` | 记录委屈、受伤、害羞；按会话或按 QQ 号 | 需要「对谁有情绪」时；用户维度适合跨群延续 | 工作模式 `active`、对象选择、可选模型 | 关系/日记/记忆仍按会话隔离；不自动回填旧记录 |
| 关系 | 按真实来源展示对象、日列表、实时 3D 图与编辑 | 需要好感度、阶段、边界和关系校正时 | 真实会话来源；管理员编辑权限 | 不创建不存在的会话；不替代记忆正文 |
| 作息与精力 | 睡眠总开关、时区、夜间/沉睡/午休、手动入睡/叫醒 | 希望 TA 有作息和精力变化时 | 有效 IANA 时区；调度 | 关闭即清醒、精力 100%；不会自动开启睡眠 |
| 主动聊天 | 按 QQ 号码名单、随机等待、安静/活动时段、免打扰、额度、未回应退避主动发送 | 希望 TA 主动找人说话时 | QQ OneBot 私聊/群聊真实来源；总许可 + 群许可 | 不保证平台最终送达；不是定时任务插件 |
| 宿主定时问候让行 `proactive_native_yield` | 同会话宿主定时问候前后 15 分钟暂停随机主动 | 宿主已有早安/定时问候，避免撞车 | 只读宿主 `cron_jobs` | 不修改/删除宿主任务；不影响承诺、晚安、补课 |
| 承诺 | 把「稍后再做」登记为待办，到期执行；支持取消、重试、未知结果保护 | 需要记住约定并到期兑现时 | 聊天模型；图片承诺需 LH 执行 | 不替代通用日程/提醒插件；不盲目重试未知结果 |
| 日记与梦境 | 手动/自动生成私人日记、想象梦境；可选配图 | 需要角色内省和长期经历时 | 人格、聊天模型、可选记忆/图片能力 | 日记/梦境不自动同步到其他记忆库；主观内容不当事实 |
| 记忆 `memory_enabled` / `auto_memory_ingest_enabled` / `livingmemory_enabled` | 选择 LivingMemory 或本地向量/本地 lite；读写分别授权 | 需要长期偏好、关系和经历时 | LivingMemory 公开接口，或 embedding Provider | 不建立第二份与其它插件重复的长期库；不绕过会话授权 |
| 掌控感与表达 | 底气调节负面情绪与说话风格；六项投影 | 需要情绪影响表达但不改变事实时 | 模型写入底气；规则投影 | 不改变好感分、事实依据或任务许可 |
| 人格 / 风格摘要 / 提示词 | 跟随或指定原生人格；风格摘要、人物性格、独立提示词开关 | 需要统一角色语气时 | 宿主人格；风格摘要可调用主模型 | 不改写宿主人格；风格摘要只给本插件使用 |
| 图片任务协作 | LE 登记原承诺与结案；LH 领取、改词、生成、发送 | 需要承诺生图时 | LH 对应版本；生图 Provider | LE 不替代 LH 的生图执行与发送回执 |
| 诊断日志 | 页面导出近 3 天脱敏 ZIP | 排查情绪、保存、发送问题时 | 管理员身份 | 不证明真实平台送达或模型效果 |
| 管理 API / 页面 | Bearer 管理员、CAS 保存、自动刷新、草稿保留 | 管理配置、关系、承诺、诊断时 | 管理员身份 | 资源 token/客户端身份参数不授予管理权 |

## 依赖关系

- 宿主：AstrBot 4.29.1–4.29.4，Python ≥3.12；人格、主模型、TTS、分段由 AstrBot 管理。
- 平台：QQ OneBot 支持私聊/群聊状态、回复注入和 QQ 号码名单主动聊天；QQ 官方机器人、Telegram、Discord 为源码接入，真实送达需单独验收；WebChat 不支持。
- 可选配套：LivingHello（回复闸门、图片执行、回执）、LivingMemory（长期记忆公开接口）。
- 本地向量记忆需要有效 Embedding Provider；启用 LivingMemory 时不需要本地 embedding。
- 模型凭据在 AstrBot Provider 管理；LE 只保存 Provider ID。

## 与其它插件的重叠与取舍

### 主动消息（Proactive Chat，DBJD-CR）

- 它是**主动发送器**：支持私聊/群聊主动消息、上下文感知、持久化数据、动态情绪、免打扰、TTS 和独立 WebUI。
- 与 LE 的重叠：主动发送、情绪驱动、免打扰/安静时段、额度/退避，以及可能的 TTS 表达。
- 取舍：
  - 要情绪/关系/作息/承诺/日记梦境联动、QQ 号码名单和宿主问候让行：**只用 LE 主动聊天**，关闭/卸载 Proactive Chat。
  - 要独立 WebUI、TTS 或纯主动消息功能：**只用 Proactive Chat**，关闭 LE 的主动聊天总许可；如果不想让两套情绪状态分叉，把 LE 设为 `observe_only` 或关闭情绪模型/对象情绪。
  - 不要同时开启两个发送器：会重复发送、各自记账、冷却互不感知，用户侧表现为抢话或重复问候。

### AstrBot 宿主定时问候 / 主动任务

- 宿主定时任务负责按计划生成和发送；LE 的 `proactive_native_yield` 只读任务表，在同一会话问候前后各 15 分钟让行。
- LE 不修改、不删除、不创建宿主任务；关闭让行后不再避让。
- 如果只想要宿主定时问候，不要开启 LE 随机主动；如果两者都要，保留让行并避免把随机主动的安静时段设成同一时间。

### LivingMemory

- LivingMemory 负责长期记忆的存储、Embedding、关键词/向量/图谱召回、归档与衰减；LE 只通过公开接口读取/写入。
- `livingmemory_enabled=true` 时使用 LivingMemory；关闭时走本地向量（需要 embedding）或本地 lite。
- 不要同时启用两个会写入同一批对话的长期记忆插件：会重复写入、重复召回、费用和事实不一致。
- `memory_enabled` 控制读取，`auto_memory_ingest_enabled` 控制自动写入，二者独立；关闭 LE 接入不等于关闭 LivingMemory 自己的归档/写入。
- 日记、梦、摘要和记忆是不同材料：主观日记/梦境不会自动变成事实，也不会自动同步到其他记忆库。

### LivingHello

- LH 负责入站回复闸门、回复整理、图片理解、生图执行和发送回执；LE 负责状态、主动行为与承诺。
- 支持同时安装；通过 LH 的 `coupling_livingemotion_enabled` 读取当轮情绪/关系/可用性。
- 图片承诺：LE 登记原承诺与结案，LH 领取、改词、生成、发送；不要再装第三个生图插件处理同一 `promise_id`。
- 不要同时运行两个「是否回复」闸门；LH 的判定日志不能证明 LE 主动消息已送达。

### 其它情绪 / 关系 / 人格演化插件

- LE 负责原生人格的情绪、关系、作息状态；另一个带好感度/情绪/人格演化的插件同时写入，会造成数值和表达冲突。
- 取舍：只保留一个状态写入者。要用另一个插件，先把 LE 设为 `observe_only` 或关闭对应模块；不要指望两套状态自动合并。

### 其它睡眠 / 免打扰 / 静默插件

- LE 睡眠可 `block_chat`；如果另一个插件更早停止事件，消息到不了 LH 判定，也可能绕过 LE 的主动发送检查。
- 只保留一个睡眠/免打扰负责人：LE 或宿主/其它插件，不要叠加多层拦截。

### 其它提醒 / 待办 / 日记插件

- 提醒/待办：LE 承诺负责到期执行；再装一个提醒插件会对同一事项重复发送。二者选一。
- 日记/梦境：LE 自己生成和保存；再装一个日记插件会重复生成、重复计费、产生两份记录。二者选一。

### TTS / 人格 / 分段

- 人格、TTS、分段属于 AstrBot 宿主配置；LE 的风格摘要只给本插件使用，不改写宿主人格。
- 不要用另一个插件改写同一份宿主配置；否则保存冲突或表达不一致。

## 配置归属速查

| 归属 | 负责内容 |
| --- | --- |
| AstrBot 宿主 | 人格、主对话模型、TTS、原生分段、宿主定时任务、Provider 凭据 |
| LivingEmotion | 情绪、关系、作息/精力、主动聊天、承诺、日记/梦境、记忆提供者、风格摘要 |
| LivingHello | 入站闸门、碎片、回复整理、图片理解、生图执行、发送回执、诊断 |
| LivingMemory | 长期记忆存储、Embedding、召回、归档与衰减 |

原则：**每个行为只在一个归属处配置**。不要在 LE 里配置 LH 的闸门，也不要用 LE 的开关代替 LivingMemory 的写入开关。

## Agent 自检顺序

1. 先按上表确认功能归属，不要跨插件猜配置。
2. 检查插件列表：是否已经装了同类主动发送器、情绪/好感度插件、记忆库、提醒/日记插件或生图工具。
3. 检查开关是否真的启用：LE 默认关闭对象情绪/情绪模型/随机主动/自动日记/梦境/长期记忆；主动聊天还需总许可和群许可。
4. 检查配置位置：情绪/关系/作息/承诺/日记在 LE，记忆在 LivingMemory 或 LE 本地路径，闸门/图片执行在 LH，人格/模型/TTS 在宿主。
5. 排查「为什么没发」：依次核对 `mode`、总/群许可、真实来源名单、时段、静音、安静时间、额度、未回应退避、宿主让行。
6. 不要把 `prepared`/`generated` 当成已发送；`sent` 只表示发送接口受理，不等于用户已读。
7. 不确定时保持保守，并在报告里写清「未验证/未实测」边界。

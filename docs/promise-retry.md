# 承诺重试与收尾

适用LE 0.10.2、LH 2.10.0。

在LE「设置 → 承诺代办」设置 `promise_retry_limit`，整数0–10，默认5。它表示初次失败后最多自动重试多少次，0关闭。文本明确发送失败、图片限流或暂时不可用的延迟重试每次间隔5分钟，次数落库。图片改词还受LH「AI生图」的 `prompt_guard_retry_limit` 限制，范围0–10，保留默认2。实际改词上限取LH次数与LE剩余预算的较小值；延迟重试和改词共用LE预算。两端均设10时最多初次1次加自动重试10次；LE默认5、LH默认2时最多改词2次。

只有明确内容拒绝或描述过长才进行等义局部调整；提供方错误、额度用尽和未知结果先暂停并给一次可取消的说明。未知结果保留请求证据，不因重启、追问或取消再次生图。只有明确未发送的拒绝才重新发送追问；追问本身结果未知不重复发。

在LE同一设置页配置 `promise_wait_timeout_hours`，整数1–168，默认24。进入 `waiting/unknown` 时记住 `waiting_since`；刷新、追问不延长期限。旧库补字段并使用原 `updated_at`，不会因升级再延长一天。到期记为 `failed/waiting_timeout` 并释放名额，保留请求ID、动作阶段和失败内容，不记录为图片已完成。

主动行为页展开任务后点击「取消后续处理」，页面自动读回列表。聊天取消标记沿用同一事务入口。`running` 不可取消；`waiting/unknown/scheduled/awaiting` 可取消。身份、代次和状态在事务中核对，多目标存在冲突时全组不取消。取消不撤回已发送图片，也不表示上游请求已经撤销。

重试前持久化准备候选和尝试编号。重启后恢复同一候选和计数；处在生成或发送阶段的任务进入核对，不盲目重新执行。未知任务也计入未完成名额，不能借未知状态绕过上限。

LH 2.9.6 的延迟门面保留 `reason_code`、`exception_type` 与 `requested`。权限或参数预检失败明确标为未请求；超时、请求回执丢失或投递未知禁止自动重新生图，使用真实核对说明。业务原因与异常类型落库，不保存上游异常正文或密钥。
